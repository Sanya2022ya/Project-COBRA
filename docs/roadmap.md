# Дорожная карта

Обозначения: `[ ]` — не начато, `[~]` — в работе, `[x]` — готово.
Каждая задача — отдельный коммит, код + тесты. Сроки ориентировочные.

## Семестр 3 (октябрь 2026 – январь 2027)

Пункты индивидуального плана: 1.1 синтез алгоритма, 1.2 тестирование и оптимизация,
1.3 схема алгоритма для сценариев нагрузки, 2 публикация.

### Этап 0. Каркас проекта (до ~12 окт)

- [x] **0.1** Многомодульный Maven: родительский `pom.xml` + `cobra-core`, `cobra-workload`, `cobra-sim`. Java 25, JUnit 5, `mvn -q verify` проходит.
- [ ] **0.2** `README.md` (кратко о проекте, как собрать).

### Этап 1. Минимальное ядро без арбитра (до ~17 окт)

- [ ] **1.1** `Ticker` (интерфейс) + `SystemTicker` + `ManualTicker` для тестов/симулятора.
- [ ] **1.2** `Weigher<K,V>` и учёт байтов (+ надбавка на запись, по умолчанию 64 Б).
- [ ] **1.3** `Region<K,V>`: хранилище + LRU по байтам, `get(key, loader)`, вытеснение при превышении доли, изменение доли на лету (`resize`).
- [ ] **1.4** Статистика региона: попадания, промахи, λ (для метрик) и c (EWMA с затуханием по времени через `Ticker`, настраиваемый полупериод), время загрузки измеряется самим ядром.
- [ ] **1.5** `Cobra` + builder: общий бюджет, регистрация регионов с min/max.
- [ ] **1.6** `AllocationStrategy` (интерфейс) + `StaticEqual`, `StaticProportional` (по объёму данных и по λ·c); `Cobra.rebalance()` вызывается извне. «Общий кэш» — конфигурация с одним регионом, а не стратегия.

Критерий готовности: тесты на вытеснение, учёт байтов, измерение стоимости через `ManualTicker`.

### Этап 2. Профиль нагрузки «биллинг» (до ~20 окт)

- [ ] **2.1** Формат профиля (YAML): регионы (число ключей, распределение популярности — Ципф α, распределение размеров, стоимость промаха), фазы (длительность, интенсивность по регионам).
- [ ] **2.2** Генератор потока запросов `(time, region, key, size, cost)` с фиксируемым seed (воспроизводимость).
- [ ] **2.3** Профиль `billing.yaml`: справочники/тарифы, лицевые счета, начисления, отчёты; фазы «день», «ночной расчёт», «конец месяца». Числа — начальные оценки, калибруются позже.

### Этап 3. Симулятор и проверка смысла (до ~27 окт) — **контрольная точка**

- [ ] **3.1** Прогон потока через `Cobra` на виртуальных часах; загрузчик сдвигает часы на стоимость из профиля.
- [ ] **3.2** Метрики во времени → CSV: L (время хранилища на промахи), Hit Ratio, доли регионов.
- [ ] **3.3** Оптимум задним числом: кривые промахов каждого региона по трассе (стековые расстояния, по байтам) + оптимальное распределение бюджета. Два оптимума: **статический** (одно распределение на всю трассу) и **пофазный** (своё распределение на каждую фазу). *Сначала обсудить метод с автором.*
- [ ] **3.4** Сравнение: StaticEqual, StaticProportional (по объёму данных: ключи × средний размер; по λ·c), общий кэш, статический и пофазный оптимумы — при нескольких бюджетах.
- [ ] **3.5** Скрипт графиков (Python/matplotlib или аналог) из CSV.

**Контрольная точка:** разрыв «лучшая альтернатива → оптимум» по L (отдельно для статического и пофазного оптимума).
Если значимый (ориентир ≥15–20%) — продолжаем. Если мал — обсуждаем корректировку профиля/темы.

### Этап 4. Арбитр КОБРЫ (до ~17 ноя)

- [ ] **4.1** Теневой список (ключи + размеры вытесненных объектов, объём Δ) → оценка ĥ⁺. *Сначала обсуждение.*
- [ ] **4.2** Учёт попаданий в хвост LRU объёмом Δ → оценка ĥ⁻. *Сначала обсуждение.*
- [ ] **4.3** `CobraArbiter` (стратегия): период T, шаг Δ, гистерезис ε, ограничения min/max. *Сначала псевдокод.*
- [ ] **4.4** `HitArbiter` = тот же арбитр с cᵢ = 1 (модель класса Memshare/Cliffhanger).
- [ ] **4.5** (опционально) Один регион с вытеснением GreedyDual-Size как эталон стоимостного вытеснения.
- [ ] **4.6** Полная таблица сравнения в симуляторе; доля закрытого разрыва до оптимума.

### Этап 5. Защита кучи (до ~1 дек)

- [ ] **5.1** Абстракция сигнала давления памяти (в симуляторе — сценарий «приложению нужна память», в JVM — `MemoryPoolMXBean`, порог после GC).
- [ ] **5.2** AIMD-управление общим бюджетом; при сжатии память забирается у регионов с min loss.
- [ ] **5.3** Сценарий в симуляторе: ночной расчёт съедает часть памяти — сравнение со статическим зоопарком.

### Этап 6. Эксперименты (до ~20 дек)

- [ ] **6.1** План эксперимента (теория планирования эксперимента): факторы — число регионов, разброс стоимостей, бюджет, частота смены фаз; отклик — L, доля закрытого разрыва.
- [ ] **6.2** Подбор Δ, T, ε; чувствительность.
- [ ] **6.3** (если доступно) публичные трассы (например, Twitter cache-trace: кластеры как регионы).
- [ ] **6.4** Сводные таблицы и графики для отчёта и статьи.

### Этап 7. Минимальное демо (если останется время; иначе — семестр 4)

- [ ] **7.1** `cobra-demo`: Spring Boot, «биллинг», PostgreSQL в Docker, генератор HTTP-нагрузки по профилю.
- [ ] **7.2** `CacheFacade` + режимы: зоопарк Caffeine / общий Caffeine / Redis / КОБРА; L меряется на фасаде.
- [ ] **7.3** Micrometer → Prometheus → Grafana: L во времени, доли регионов.

### Январь
